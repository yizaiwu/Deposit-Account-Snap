# 存匯端末一秒抓帳程式

以前常在存匯拆傳票到晚上 8、9 點下班，現在自己 Vibe Coding 了一個自動拆傳票抓帳程式，希望未來辛苦的存匯同仁不用煩惱結帳不平。

雖然小弟在 113 年有員工創意提案「雙邊起帳系統」，希望從源頭避免存匯轉帳不平，但提案沒有被採用。既然公司系統在源頭暫時沒辦法改進，就由小弟自己開發程式亡羊補牢幫忙抓帳，讓辛苦的存匯同仁不用再浪費時間在抓帳上面，增進工作效率，加強本行競爭力。

## 專案介紹

「存匯端末一秒抓帳程式」是一個單一 HTML 檔案的本機 Web App。使用者只要將 HP0010 序時記錄查詢輸出的 CSV 檔匯入，即可快速檢查存匯轉帳交易是否借貸不平。

程式完全在瀏覽器本機執行，不需要安裝伺服器、不需要上傳資料，也不會把 CSV 傳到外部服務。

## 功能特色

- 匯入 CSV 後自動分析交易資料。
- 只分析 `交易摘要` 為 `H`、`SH` 且有 `交易金額` 的交易。
- 自動加總 `借貸 = 0` 的借方金額。
- 遇到下一筆 `借貸 = 1` 的貸方交易時，自動比對借貸是否平衡。
- 若不平，輸出差額與方向：
  - `借貸不平，金額10元，貸方多`
  - `借貸不平，金額30元，借方多`
- 支援交易金額含千分位逗號，例如 `"98,233"`。
- 提供明亮 / 黑暗護眼模式切換。
- 單檔 HTML，可直接用瀏覽器開啟。

## 使用方式

1. 下載或開啟 `存匯端末一秒抓帳程式.html`。
2. 用瀏覽器直接開啟該檔案。
3. 點選「選擇 CSV 檔案」。
4. 匯入 HP0010 序時記錄查詢輸出的 CSV。
5. 查看分析結果。

## CSV 欄位格式

CSV 需包含以下欄位：

```csv
櫃員,櫃檯機號,交易時間,端末交易代號,交易代號,交易摘要,歸戶/歸戶編號/其他,借貸,更正記號,主管,交易金額,訊息代號
```

其中本程式主要使用：

- `交易時間`
- `交易摘要`
- `借貸`
- `交易金額`

## 運作原理

程式讀取 CSV 後，會先解析每一列交易資料，並正確處理 CSV 雙引號與逗號，例如交易金額 `"98,233"` 不會被誤拆成兩個欄位。

接著程式會依照以下規則篩選資料：

- `交易摘要` 必須是 `H` 或 `SH`。
- `交易金額` 必須有值，且可轉換為數字。
- `借貸` 必須是 `0` 或 `1`。

分析邏輯如下：

1. `借貸 = 0` 視為借方，連續交易會累計借方金額。
2. 遇到下一筆 `借貸 = 1` 時，視為貸方結算點。
3. 將目前累計的借方金額與該筆貸方金額比較。
4. 若金額相同，判定為借貸平衡。
5. 若金額不同，計算差額並判斷是借方多或貸方多。
6. 比對完成後清空借方累計，繼續分析後續交易。

範例：

```text
借方：6,191 + 65 + 91,967 = 98,223
貸方：98,233
差額：10
結果：借貸不平，金額10元，貸方多
```

## 技術棧

- HTML5
- CSS3
- Vanilla JavaScript
- FileReader API
- LocalStorage

本專案沒有使用任何前端框架、後端服務、套件管理器或外部 CDN。所有功能都集中在單一 HTML 檔中，方便存放、攜帶、稽核與離線使用。

## 隱私與安全

- CSV 只會在使用者自己的瀏覽器中解析。
- 程式不會上傳檔案。
- 程式不會連線到任何外部 API。
- 程式不會儲存交易資料。
- `localStorage` 只用來記住明亮 / 黑暗模式偏好。

## 適用情境

本工具適合用於輔助檢查存匯端末交易中的借貸不平狀況，協助縮短人工拆傳票與抓帳時間。

本工具僅作為輔助檢查用途，實際帳務判斷仍應以公司正式系統、內部規範與主管覆核為準。
